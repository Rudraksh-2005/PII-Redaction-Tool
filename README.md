# PII Redaction Tool

## Approach
This project utilizes a hybrid approach for Personally Identifiable Information (PII) redaction. It leverages **Microsoft Presidio** (which uses spaCy's Named Entity Recognition and regex pattern matchers) to detect PII entities such as Names, Email Addresses, Phone Numbers, Organizations, Locations, SSNs, and more. 
For anonymization, it replaces the detected PII with fake synthetic data generated by the **Faker** library. A mapping dictionary is maintained during runtime to ensure that consistency is maintained (e.g., if "John Doe" is mapped to "Peter Parker", it will remain consistent throughout the document).

## Tradeoffs and Limitations
- **False Positives:** NER models can sometimes classify general nouns or non-sensitive identifiers as PII. For instance, generic company terminology might be flagged as an `ORGANIZATION`. 
- **False Negatives:** Complex or heavily formatted edge-cases in phone numbers or international addresses might slip past Presidio's default recognizers if they don't match the specific en-core-web-lg patterns or built-in regex rules.
- **Consistency vs Memory:** The current implementation keeps an in-memory dictionary of mappings. For extraordinarily large datasets, this could lead to higher memory consumption, but it's essential for maintaining context.
- **Semantic Structure:** By replacing entities with synthetic data of varying lengths, the document layout could shift, though the semantic meaning is preserved.
